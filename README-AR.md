# SUKUK LAB — التحديث الاحترافي للموقع

**هذه حزمة تحديث للكود الموجود في مستودع `roseal3tb/sukuk-lab`، وليست مستودعًا كاملًا أو ملف ZIP تنشره GitHub تلقائيًا.** صُممت لتُنسخ الملفات من داخلها إلى المشروع القائم مع الحفاظ على بقية ملفاته، وتكامل Supabase، ومسارات الإدارة والأمان الموجودة مسبقًا.

## ما الذي تغير؟

- تصميم عربي RTL جديد: واجهة سينمائية، هندسة ذهبية متحركة، عناوين متتابعة، وحركة تدريجية أثناء التمرير.
- بطاقات ورش العمل والجلسات ودراسة الحالة أصبحت تفاعلية وذات إيقاع بصري مختلف.
- الـTimeline ثلاث محطات في 8 و9 و10 نوفمبر 2026، مع خط يتقدم أثناء التمرير.
- هوية الألوان حصريًا: `#121212` و`#1E1E1E` و`#C9A24A` و`#E8E8E8` و`#F6F4EE`.
- نموذج التسجيل أُعيد تصميمه دون إزالة ربط Supabase / RPC السابق. يُظهر النجاح فقط بعد استجابة الحفظ الفعلية.
- مراعى توافق الهاتف، التنقل بلوحة المفاتيح، وتقليل الحركة `prefers-reduced-motion`.
- المحتوى التعريفي من ملفات البرنامج الثلاثة فقط. **تاريخ 8 نوفمبر هو تحديث منك وليس من الملفات الأصلية.**

## كيف تُطبق التحديث على GitHub؟

1. افتح مستودع `https://github.com/roseal3tb/sukuk-lab`، واحتفظ بنسخة احتياطية أو أنشئ فرعًا جديدًا قبل الاستبدال.
2. فك ضغط ZIP ثم انسخ مجلدَي `src/` و`supabase/` الموجودين في الحزمة إلى مجلد المشروع الأصلي **مع دمج المجلدات واستبدال الملفات المتطابقة فقط**. لا تحذف الملفات القديمة الأخرى.
3. لرفعها من واجهة GitHub استخدم **Add file → Upload files** بعد فتح مسار الملف الصحيح، أو استخدم Git محليًا:
   ```bash
   cp -R path/to/sukuk-lab-update/src ./src
   cp -R path/to/sukuk-lab-update/supabase ./supabase
   git add src supabase
   git commit -m "Premium Sukuk Lab design and Nov 8 registration update"
   git push
   ```
   **لا ترفعي ملف ZIP نفسه إلى جذر GitHub وحده وتنتظري تغيّر الموقع**؛ يجب دمج محتوياته.
4. شغلي من مجلد المشروع `npm install` ثم `npm run build` أو `bun install` ثم `bun run build` حسب طريقة تشغيل المستودع، وراجعي الأخطاء. هذه الحزمة اجتازت فحص صياغة TypeScript للملفات المعدلة، **لكن لا يمكن تأكيد البناء الكامل محليًا** لأن بيئة الفحص لم تستطع تحميل الاعتماديات من الإنترنت.
5. **لإتاحة التسجيل فعليًا:** افتحي Supabase SQL Editor المتصل بالمشروع الصحيح، وراجعي ملف `supabase/migrations/20261104_open_registration.sql` ثم نفذيه. تحديث الواجهة وحده لا يفتح التسجيل: قرار الفتح محفوظ في جدول `registration_settings` في قاعدة البيانات.
6. جرّبي طلبًا تجريبيًا بأسم وبريد تجريبيين في البيئة المناسبة وراجعي ظهوره في قاعدة البيانات/لوحة الإدارة قبل نشر رابط التسجيل. احذفي بيانات الاختبار بعد الانتهاء.

## لتعديل التاريخ لاحقًا

عدّلي قيمة `PROGRAM_START_DATE` داخل `src/lib/program.ts` فقط. جميع الأيام الثلاثة والتواريخ المعروضة تتغير تلقائيًا. لا تضيفي ساعات للبرنامج من عندك: المصدر لم يحددها.

## نقاط مهمة قبل النشر

- فتح التسجيل في Supabase **لا يضمن أن طلبات المستخدمين ستُحفظ حتى يُختبر اتصال المشروع المنشور وقواعد RLS ودالة `submit_application`**. أدرجنا SQL بسيطًا لفتح نموذج التسجيل الموجود، وليس إنشاء خدمة بيانات جديدة.
- حافظي على `.env` وملفات التكامل الحالية كما هي؛ **لا تضعي `service_role` أو مفاتيح سرية في واجهة الموقع**.
- لوحة الإدارة `/admin` في المستودع السابق تتطلب إنشاء حساب مدير وتعيين دور `admin` من جهة موثوقة. هذه الحزمة لم تُنشئ مديرًا تلقائيًا لأسباب أمنية.
- الشريك الراعي والمستضيف مأخوذان من بروشور البرنامج؛ تأكدي من بقائهما معتمدين قبل الإطلاق.
- الجدول الزمني يصف *أيام البرنامج* وليس أوقات المحاضرات. العناوين والأنشطة مأخوذة من الصفحة الثامنة من ملف المقترح.
- قد توجد أخطاء TypeScript قديمة في بقية المستودع؛ لم نعدّل الملفات غير اللازمة للتصميم حتى لا نخاطر بوظائف لا تخص الطلب.

## قائمة الملفات المضافة أو المستبدلة

- `src/routes/index.tsx` — الصفحة الرئيسية.
- `src/routes/register.tsx` — نموذج التسجيل.
- `src/components/site/SiteHeader.tsx` — الرأس والقائمة والفوتر.
- `src/styles.css` — الهوية والحركة والتجاوب (ويحتفظ بتوكنات واجهة الإدارة).
- `src/lib/program.ts` — ملف مركزي جديد لمعلومات الأيام والتواريخ والمحتوى.
- `src/lib/registration.ts` — التحقق ورسائل الأخطاء وحماية تصدير CSV من المعادلات.
- `supabase/migrations/20261104_open_registration.sql` — تفعيل التسجيل على قاعدة البيانات القائمة (يحتاج تنفيذ يدوي).

**لم يُجرَ أي تعديل على Lovable، ولا على GitHub الأصلي.** هذه ملفات جاهزة للنسخ والتعديل المحلي.
