# SUKUK LAB | مختبر الصكوك

موقع عربي RTL للبرنامج التطبيقي في **الصكوك وأدوات الدين** من تنظيم **مبادرة إثمار المالية – جامعة الملك سعود**.

## مصدر المحتوى (لا تُختلق تفاصيل غير واردة)

- `SUKUK LAB BLACK.pdf`: الاسم، الشعار النصي، الفكرة والألوان.
- `Sukuk-Lab-Proposal.pdf`: أهداف البرنامج الخمسة، الفئة المستهدفة، مسار الأيام الثلاثة، دراسة الحالة والمخرجات.
- `SukukLab-Brochure-A5.pdf`: المعلومات التعليمية والعلامات والشركاء.
- التاريخ `8–10 نوفمبر 2026` **تعديل من صاحبة المشروع** بدل `25–27 أكتوبر 2026` الوارد بالملفات الأصلية.

لا تُعرض مواعيد ساعات أو أسماء متحدثين أو أرقام تواصل لا يثبتها المصدر. وفق غلاف البروشور: الجهة المنظمة إثمار، الراعي الرئيسي **صكوك كابيتال** والشريك المستضيف **الأكاديمية المالية**. يجب إعادة تأكيد اعتماد الشراكات قبل الإطلاق.

## التصميم

- الهوية `#121212` و`#1E1E1E` و`#C9A24A` و`#E8E8E8` و`#F6F4EE`.
- الهيرو الحالي حافظ على تخطيطه ونصوصه؛ استُبدلت الدائرة برسمة صكوك خفيفة في `public/hero/sukuk-certificate.svg`.
- تقسيم المحتوى: عن البرنامج، التجربة، دراسة الحالة، الـTimeline ثلاثة أيام، الأهداف الخمسة، المخرجات الأربع، الفئة المستهدفة، الشركاء، التسجيل.
- حركات متدرجة قابلة للإيقاف تلقائيًا عند `prefers-reduced-motion`.

## التشغيل محليًا

يتطلب Node.js وبن (Bun)، والمشروع يعتمد حاليًا على حزمة البناء `@lovable.dev/vite-tanstack-config` لكنه **لا يتطلب محرّر Lovable لتعديل الكود**.

```bash
bun install --frozen-lockfile
bun run dev
bun run build
bunx tsc --noEmit
bun run test
bun run lint
```

ملفات الواجهة الرئيسية: `src/routes/index.tsx` و`src/styles.css`، ملف المحتوى المركزي: `src/lib/program.ts`، التسجيل: `src/routes/register.tsx`، لوحة الإدارة: `src/routes/admin.tsx`.

لتعديل الموعد عدّلي فقط `PROGRAM_START_DATE` داخل `src/lib/program.ts`.

## التسجيل: قبل إتاحة الموقع للعامة

**الموقع لا يُعتبر جاهزًا لتلقي طلبات حقيقية لمجرد نجاح البناء أو ظهور زر التسجيل.** يلزم التأكد من Supabase الفعلي؛ ولا ينبغي نشر بيانات طلبات تجريبية.

1. اضبطي إعدادات النشر العامة `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` على الخدمة الصحيحة؛ لا تضعي مفاتيح `service_role` في المتصفح.
2. إذا كانت قاعدة البيانات جديدة فقط، راجعي مخطط `drizzle/migrations/0000_migration.sql` أولًا. **لا تعيدي تطبيقه عشوائيًا على قاعدة موجودة.**
3. نفّذي `supabase/migrations/20261104_align_registration_form.sql` **على قاعدة المشروع الصحيحة** لمواءمة نموذج التسجيل مع 12 حقلًا وحفظ البيانات والتحقق وقائمة الانتظار، ثم تأكدي من سياسات RLS.
4. اختبري طلبًا تجريبيًا، وتأكدي من ظهوره للإدارة فقط وبالحقول الكاملة، وجرّبي الرفض والتكرار والاستيعاب وقائمة الانتظار. عالجي حماية الطلبات من الإرسال الآلي قبل النشر الواسع.
5. بعد التحقق، شغّلي `supabase/migrations/20261104_open_registration.sql` لفتح التسجيل فعليًا؛ **ملف SQL في GitHub وحده لا يغيّر قاعدة البيانات**.
6. أنشئي حساب مدير بصلاحية `admin` من جهة موثوقة؛ صفحة `/admin` ليست مفتوحة للعامة.

## مراجعة ما قبل الاعتماد

راجعوا معاينة Vercel من فرع المراجعة على الكمبيوتر والجوال، خصوصًا رسم «صكوك»، وضوح النص فوقه، تجاوب البطاقات، محطات الـTimeline، نموذج التسجيل، إدارة الطلبات، وأداء الهاتف.

ملف GitHub Actions `.github/workflows/quality.yml` ينفّذ البناء وفحوص TypeScript والاختبارات وESLint، ويُنتج **ZIP كامل للمستودع** بالإضافة إلى لقطات معاينة حين يتوفر Chrome على بيئة التشغيل.

**النسخة للمراجعة فقط:** `review/premium-final-20261104`، ولا تُدمج بـ `main` أو تُنشر للإنتاج قبل اعتمادك.
